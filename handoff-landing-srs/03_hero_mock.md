# 03 · 히어로 목업 개편

**대상**: `src/components/landing/HeroProductMock.tsx` (1,325줄)
**시안**: `랜딩 히어로 목업.dc.html` → `2a`(데스크탑) · `6a`(모바일)

---

## 문제

목업이 데스크탑에서도 사실상 "모바일 화면 확대판"입니다.

`isMobile`이 거의 전부 **배율 계수**로만 쓰입니다 — `const S = isMobile ? 1 : 1.3`.
8개 탭 중 레이아웃이 실제로 갈리는 건 `PaneBlank` 하나뿐이고, 나머지 7개는 같은 레이아웃을 1.3배 확대합니다.

그리고 목업 프레임이 브라우저 창도 폰 프레임도 아니라 그냥 흰 카드(`borderRadius: 16` + 그림자)여서,
보는 사람에게 데스크탑인지 모바일인지 단서가 없습니다.

---

## 방향 — 프레임을 화면 폭에 따라 갈아끼운다

| | 프레임 | 본문 폭 |
|---|---|---|
| 데스크탑 | 앱 창 크롬 (신호등 + 화면 제목 줄) · **사이드바 없음** | 641px |
| 모바일 | 프레임 없음 · 얇은 테두리 + 화면 제목 줄만 | 358px |

폰으로 보는 사람은 이미 폰을 들고 있으니 폰 그림이 설명해 줄 게 없습니다. 가로를 다 쓰는 게 이득입니다.
데스크탑에서는 창 크롬과 641px 본문 폭이 "데스크탑 화면"을 말합니다 — 그 폭이 있어서 유형 카드가 2열로 깔립니다.

### 폐기한 안

- 사이드바(접힌 아이콘 레일 / 전체 메뉴) — 641px에서 본문을 더 좁힘
- 창 전체 축소 + 콜아웃 확대 — 축소된 본문 글자가 읽는 용도가 못 됨
- 오른쪽으로 넘치는 창 — CTA와 진행 표시가 오른쪽에 있어 잘리면 곤란
- 모바일 폰 프레임 — 폰 안에 폰

---

## 모바일 창 규격 (6a)

```
창       358 × 560px
  제목 줄     38px  (☰ + 화면 이름 + 스크롤 힌트)
  스크롤 영역 522px  overflow-y: auto; overscroll-behavior: contain
페이드    하단 34px, linear-gradient to rgba(255,255,255,0.92), pointer-events: none
안쪽 배경  흰색  ← 02(7b) 확정에 따름
```

- **560px은 쓸 수 있는 화면 높이의 약 75%** (iPhone 14 기준). 폰 화면답게 크고, 위의 헤드라인·CTA가 같이 보이는 지점
- 내용은 **축소하지 않고 1:1**. 폰에서 전체를 줄여 넣으면 글자가 9px가 되어 못 읽음
- **8개 탭이 같은 높이를 쓴다.** 탭마다 높이가 다르면 5.5초마다 히어로가 들썩임. 짧은 화면은 여백이 남고, 긴 화면(퀴즈 만들기)은 안쪽에서 스크롤
- 페이드는 가리개가 아니라 "더 있다"는 표시

### ⚠ 구현 시 두 가지

1. **스크롤이 두 개 겹칩니다.** 폰에서 페이지를 넘기려고 쓸어올릴 때 손가락이 목업 위에 있으면 목업이 스크롤됩니다. `overscroll-behavior: contain`으로 페이지까지 번지는 것만 막았고, 첫 스와이프를 목업이 먹는 건 남습니다.
2. **만지는 동안 5.5초 자동 순환을 멈춰야 합니다.** 읽는 중에 내용이 바뀌면 스크롤이 무의미해집니다.
   - `onPointerDown`/`onTouchStart`에서 타이머 정지, `onPointerLeave` 또는 일정 시간 무동작 후 재개
   - 스크롤 위치도 탭이 바뀔 때 0으로 되돌려야 합니다

부담되면 스크롤 대신 고정 높이 + 페이드로 자르는 방식이 안전합니다. 히어로 목업은 조작 대상이 아니라 구경거리입니다.

## 데스크탑 창 규격 (2a)

```
히어로 그리드   좌 443px · 우 645px · gap 64px
창             본문 641px (창 테두리 포함 643px)
  제목 줄        38px  (신호등 3개 + 화면 이름)
  본문           탭에 따라
  하단 진행선     2px  (primary 42%)
```

탭바(8개 탭)는 창 **위쪽 바깥**에 놓입니다 — `flex: 0 0 auto; min-width: 76px`인 가로 스크롤러 + 오른쪽 페이드.
데스크탑 643px에서 8개가 다 들어가고(608px), 모바일 358px에서는 스크롤됩니다.

## 작업 순서

1. 폰트 지정 걷기 + 색 토큰 교체 → **01 문서 참조**
2. 프레임 교체 — 데스크탑 앱 창 / 모바일 테두리만, `isMobile`로 분기
3. 모바일 창 560px 고정 + 안쪽 스크롤 + 자동 순환 멈춤
4. `S = 1.3` 일괄 배율을 걷고 각 요소에 실제 `sm:` 값 넣기 → **04 문서 참조**
5. 모바일에서 카드 크롬 걷기 (빈칸 채우기 제외) → **04 문서 참조**
6. 하단 3열 내비게이션 + `모르겠어요` + `이전` 아이콘만 → **04 문서 참조**
7. 퀴즈 만들기 탭 수정 → **04 문서 참조**

2·3이 눈에 보이는 변화의 대부분입니다. 4~7은 정확도 작업.
