## 1단계 — 대시보드 재구성

```
선생님 대시보드(TeacherDashboard.tsx)를 재구성해줘.

현재 문제:
- stats.totalClasses가 0으로 하드코딩되어 있다
- pendingResults가 실제 미확인 결과가 아니라 알림 개수다

바꿀 것:
1. quiz_results에 viewed_at timestamptz 컬럼을 추가하고, 선생님이 결과 화면을 열면 채운다
2. 히어로를 "확인할 결과"로 만든다 — viewed_at이 null인 제출 결과. 최대 3건을 행으로
   보여주고, 제목에 총 건수("제출된 퀴즈 5건")와 우측에 "전체 보기" 링크를 둔다
3. 히어로 아래에 "아직 안 푼 학생" 카드 — 배정됐지만 미제출인 학생 최대 3명,
   가장 오래 방치된 순서. 각 행에 재알림 버튼
4. 우측 사이드레일(296px)에 위에서부터: 새 퀴즈 만들기(초록 카드) /
   클래스·학생·만든 퀴즈 개수 요약 / 최근 만든 퀴즈 3개 / 최근 활동 클래스 3개
5. 최근 활동 클래스 카드 하단에 "내 클래스 N개 →"와 "＋ 새 클래스" 버튼
6. 기존 통계 4분할과 액션 카드 4개는 제거한다
7. 클래스 목록은 대시보드에서 렌더하지 않는다 (/classes가 담당)

상태별 분기:
- 확인할 결과 0건이고 퀴즈가 있으면: 히어로만 "모두 확인했습니다" + 새 퀴즈 만들기
  버튼으로 바꾸고, 왼쪽 카드와 레일은 그대로 유지한다
- 퀴즈 0개 + 클래스 0개(신규 가입)면: 레일을 렌더하지 않고 본문 한 컬럼(max 940px).
  히어로는 "첫 퀴즈를 만들어 보세요" + 단어 붙여넣기 입력창을 히어로 안에 직접 두고,
  아래에 "먼저 체험해 보기"와 "클래스 만들기" 2열 카드

색상: 초록 #1E6B47, 배경 #FAF8F5, 카드 흰색 + 테두리 #EBE5DE, 주의색 #B4552D.
기존 디자인 토큰이 있으면 같은 값에 매핑해줘.
```

확인: 결과 0건 / 1건 / 5건, 신규 가입 계정 각각 확인.

## 2단계 — 내 퀴즈 테이블

```
내 퀴즈 화면(Quizzes.tsx)의 카드 그리드를 테이블로 바꿔줘. 퀴즈가 173개라 카드로는 훑기 어렵다.

열: 레벨 / 제목 / 분량(N개 · N세트) / 배정 / 제출 / 만든 날짜(우측 정렬)
- 배정 열에는 배정된 학생 이름을 표시한다. 여러 명이면 "사라, 유나 +1"
- 배정이 없으면 "배정 안 됨"을 주의색(#B4552D)으로, 그 행은 배경을 #FDFCFA로 눌러놓는다
- 제출 열은 "2 / 3" 형식. 0이면 주의색
- 행 hover 시 우측에 공유·결과·배정·삭제 아이콘을 띄운다 (항상 보이면 시끄럽다)
- 단어 미리보기 칩은 테이블에서 빼고 상세 화면에만 둔다

상단: 검색 입력 + [전체 / 배정됨 / 미배정] 토글 + 레벨 드롭다운 + 정렬 드롭다운

중요 — 성능:
현재 배정 학생 이름은 expandedQuizId가 있을 때만 개별 조회한다(주석에 PGRST200 조인
회피 이유가 있음). 173개를 개별 조회하면 안 되니, 목록 진입 시 quiz_assignments를
quiz_id in (...)으로 한 번에 가져와 클라이언트에서 매핑해줘. profiles도 같은 방식으로
user_id in (...) 한 번만 조회한다.
```

확인: 173개 로딩 속도, 미배정 필터, 이름 여러 명인 퀴즈.

## 3단계 — 클래스 카드

```
내 클래스(Classes.tsx) 카드를 학생 수에 따라 다르게 보여줘.

학생 1명(1:1 수업):
- 학생 이니셜 아바타 + 학생 이름을 카드 제목으로, 부제에 "1:1 · 본명"
- 지표 3개: 배정 퀴즈 / 평균 점수 / 마지막 활동

학생 2명 이상(그룹 수업):
- 사람 아이콘 + 클래스 이름, 부제에 "학생 N명"
- 지표 3개: 배정 퀴즈 / 평균 점수 / 미제출(N명, 있으면 주의색)

공통:
- 초대 코드는 우측 상단에 작게(11.5px) 두고 클릭하면 복사된다.
  지금은 코드가 카드에서 가장 크게 보이는데, 이미 가입한 학생의 클래스에서는
  거의 쓰지 않는 정보다
- 카드 하단에 "클래스 열기" 버튼
```

## 4단계 — 퀴즈 만들기 연결 줄

```
퀴즈 만들기(QuizCreate.tsx) 상단에 다른 두 생성 화면으로 가는 연결 줄을 넣어줘.

지금 사이드바에 "퀴즈 만들기"만 있어서, 오답 복습(WrongAnswerQuizCreate)과
어휘 보강(VocabPracticeQuizCreate)이 있는 줄 모른다. 페이지를 합치지는 말고
(데이터 소스와 마법사 흐름이 다르다) 발견성만 해결한다.

- 카드 맨 위, 1단계보다 위에 한 줄: "다른 방식으로 만들기" + 칩 2개
- 칩1 "오답 복습" — 옆에 학생별 오답 개수를 작게 ("오스틴 12 · 사라 8")
- 칩2 "어휘 보강"
- 아래에 구분선

그리고 지금 5단계(제목 / 입력 방식 / 난이도 / 유형 / 추가 설정)를 3단계로 묶어줘:
1 제목과 단어 (입력 방식 탭은 이 안에 유지)
2 난이도와 유형
3 추가 설정 — 기본 접힘

입력 방식 탭(단어 입력 / 프롬프트 입력)은 지금처럼 동등한 탭으로 둔다.
프롬프트 모드에서는 단어 개수 카운터 대신 문제 수 선택(자동 / 5~40)을 보여준다.
```

## 5단계 — 오답·어휘 보강 레이아웃 통일

```
오답 복습(WrongAnswerQuizCreate)과 어휘 보강(VocabPracticeQuizCreate)의 레이아웃을
같은 골격으로 맞춰줘. 두 화면이 하는 일은 같은데(학생 → 단어 → 유형·설정) 모양이 달라서
남처럼 보인다.

단계 이름 통일: 학생 / 단어 / 유형·설정
(오답의 "대상 / 문제 선택 / 설정·생성", 어휘 보강의 "학생 선택 / 레벨·단어 / 유형·생성"을 대체)

2단계 카드 안 배치를 위에서부터 이 순서로 맞춘다:
1. 헤더 — 좌측에 카드 제목("복습할 단어" / "보강할 단어")과 "학생명 · 학생 N명 · N개 선택됨",
   우측에 전체 개수만("9개 중" / "438개 중")
2. 컨트롤 줄 — 오답은 정렬 드롭다운, 어휘 보강은 개수 + 배치 필터 + 다시 뽑기.
   같은 높이·같은 테두리 스타일의 pill로
3. 안내 스트립 — 목록에서 빠진 것의 사유와 개수 (연한 배경 + 아이콘 + 한 줄)
4. 목록 — 첫 행이 "전체 선택 / 해제" 헤더. 지금 오답 쪽은 이게 카드 우측 상단 버튼인데,
   체크박스와 같은 열에 정렬되도록 목록 헤더로 옮긴다
5. 하단 — "N개 선택됨 · 전체 N개 중" + 이전/다음 버튼

오답 목록의 각 행:
- 접힌 상태에도 대표 문장 한 줄을 보여준다. 지금은 "부르다 · 빈칸 · 2회"만 보여서
  펼치지 않으면 고를 근거가 없다. 문장에서 정답 부분을 강조하고, 뒤에 학생 답변을 붙인다
  ("친구 생일에 다 같이 노래를 불렀어요. · 올리비아 "노래를 부러요"")
- 받아쓰기 오답은 문장이 없으니 뜻을 쓴다 ("뜻 "to fix, repair" · ...")
- 펼치면 학생별 답변 전체 (지금 동작 유지)
- 유형 칩이 2개 이상이면 여러 유형에서 틀린 것이라 우선순위가 높다

어휘 보강 목록은 지금 형태(단어 + 뜻 + 예문 인라인)를 그대로 유지한다 — 예문이 보여야
"이 문장을 이 학생에게 보낼 만한가"를 판단할 수 있다.

어휘 보강 2단계의 "하루 노출 개수 / 복습 큐에 바로 추가"는 성격이 달라(퀴즈 생성이 아니라
복습 큐 적재) 3단계로 옮긴다.
```

## 6단계 — 오답 퀴즈 6유형 + 제목 입력

```
오답 복습 퀴즈(WrongAnswerQuizCreate)에서 6개 유형을 모두 만들 수 있게 해줘.
지금은 빈칸 채우기와 받아쓰기 둘만 가능하다.

가능한 이유: 이미 오답 단어를 generate-quiz에 넘겨 새 문장을 받는 경로가 있다
(현재의 "AI로 새 예문 생성" 토글). 응답에서 problems와 typeAnswerProblems만 꺼내 쓰는데,
QuizCreate.tsx가 하듯 matchupProblems / recordingProblems / sentenceMaking 등도
함께 처리하면 열린다.

3단계 구성:
1. 퀴즈 제목 — 입력 가능. 기본값 "학생명 오답 복습 · 8월 22일"
2. 문장 출처 2택: "틀렸던 문장 그대로" / "AI로 새 예문 생성"
   - 지금은 문장 없는 단어가 섞이면 "AI로 새 예문 생성을 켜주세요"라고 선생님에게 요구한다.
     그러지 말고 그 단어만 자동으로 AI 생성으로 넘겨라. 선생님이 알아야 할 구분이 아니다
3. 퀴즈 유형 6개 — 복수 선택. 선택한 유형이 모두 같은 단어에 적용된다
   (세트 수는 단어 수 ÷ 세트당 단어 수로 정해지고 유형 개수와 무관하다)
4. 추가 설정 접힘 (난이도 · 세트당 단어 수 · 번역 언어 · 제한 시간)

제목 입력의 선행 조건:
어휘 보강은 "이미 보낸 단어"를 찾을 때 ilike('quizzes.title', '%어휘 보강%')로
자기가 만든 퀴즈를 찾는다. 제목을 자유롭게 바꾸면 이 필터가 깨져 같은 단어가 반복 출제된다.
먼저 quizzes에 kind 컬럼(예: 'wrong_review' | 'vocab_practice' | null)을 추가하고,
제목 대신 kind로 조회하도록 바꾼 다음 제목 입력을 열어라.
어휘 보강 3단계에도 같은 제목 입력을 넣는다.

문장 순서 맞추기 관련 (중요):
문장 순서 맞추기 퀴즈를 "만드는 것"은 문제없다 — 오답 단어로 새 문장을 만들어 조각내면 된다.
막혀 있는 건 문장 순서 맞추기 오답을 "재료로 쓰는 것"이다. 그 오답 행은 word에 문장 전체가
들어 있어(word_magnet: word=correct_answer=문장 전체) 어휘 단위가 없다. 이건 계속 걸러라
(selectable: false 유지).
```

## 7단계 — 익힌 단어 숨김

```
선생님 오답 목록에서 학생이 이미 익힌 단어를 숨겨줘.

현재 문제:
- 졸업 처리는 wrong_answer_progress 테이블에 있다 (단어별 연속 정답 2회 → mastered_at 기록)
- 그런데 update_wa_progress는 auth.uid() 기준이라 학생이 오답 연습을 할 때만 동작한다
- 선생님 화면이 쓰는 get_class_wrong_answers는 이 테이블을 아예 참조하지 않는다
- 게다가 선생님이 배정한 복습 퀴즈는 일반 퀴즈로 저장되니 진행도에 반영되지 않는다
  → 선생님이 낸 복습 퀴즈를 학생이 다 맞혀도 아무데서도 졸업되지 않는다

바꿀 것:
1. kind = 'wrong_review'인 퀴즈를 채점할 때 update_wa_progress를 함께 호출한다
   (단어별 정답/오답을 items로 넘김)
2. get_class_wrong_answers 결과에 mastered 여부를 함께 돌려주거나,
   클라이언트에서 wrong_answer_progress를 조회해 병합한다
3. 오답 목록에서 mastered 단어는 기본 숨김. 목록 위 안내 스트립에
   "두 번 연속 맞힌 익힌 단어 12개는 숨겼습니다. [보기]" 한 줄을 둔다
   — 조용히 사라지면 왜 안 보이는지 알 수 없다

2번이 되면 목록이 자연히 줄어들어 기간 필터 같은 건 필요 없다.
```

## 미해결로 남긴 것

- 문장 순서 맞추기 오답을 재료로 쓰려면 문제 생성 시 **출처 단어**를 저장해야 합니다.
  문장 은행 행이 `word` + `sentence`로 짝지어져 있으니 생성 시점엔 알고 있는 값입니다.
  단, 과거 기록은 복구되지 않습니다.
- 그 경우에도 "어순을 틀린 것"과 "단어를 모르는 것"은 다릅니다. 문장 순서에서만 틀린 단어는
  목록에서 제외하기로 정했습니다 (다른 유형에서도 틀렸으면 포함).
